DECISIONS

  • DECISION 01

    Evolve Offers, Don't Prompt Them

    Discount, minimum order, bundle size, category, offer type and expiry form a genome. Tournament selection, crossover and mutation tune it against a weighted fitness of conversion, revenue lift and refund rate, and each run warm-starts from the last champion.

  • DECISION 02

    Hard Policy Gate On Money Actions

    A deterministic PolicyEngine caps discounts at 30% and rejects payments under INR 100 before any offer or payment link is created, so an LLM cannot hallucinate its way past the limit.

  • DECISION 03

    Audit Every Action

    Agent tools and API routes write each action, with payload, result and success flag, to an audit table that the UI reads and streams live over SSE.

  • DECISION 04

    Recover Failures Through Negotiation

    A simulated gateway rejection is returned to the buyer agent as a tool result. Its instructions tell it to fetch the champion discount and retry the checkout, which keeps the failure inside the agent loop.

  • DECISION 05

    One Backend, Two Agent Interfaces

    Both the in-process agent tools and the MCP server call the same FastAPI endpoints, so any MCP client can browse, cart and check out against the same store.
